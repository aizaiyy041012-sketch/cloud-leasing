Infrastructure

A technical overview of the compute, storage, and networking layers that make up the Cloud Leasing platform, plus how nodes are deployed and monitored once they're running.

// PLATFORM OVERVIEW

How The Platform Is Built

Every Cloud Leasing node is built from four layers: GPU and CPU compute, NVMe storage, network interconnect, and the orchestration software that ties them together. The sections below describe each layer, followed by how nodes move from a signed lease to a running workload and how the platform is monitored once deployed.

// COMPUTE

GPU & CPU Platforms

// GPU Families
RTX, A100, H800
Available as single-GPU nodes, multi-GPU nodes, and 8-GPU HGX platforms with NVSwitch, depending on family and configuration.
// CPU Platforms
Intel Xeon / AMD EPYC
Nodes pair GPUs with Intel Xeon or AMD EPYC processors, sized to the GPU configuration and workload.
// System Memory
DDR5 ECC RDIMM
Memory scales with node size, from single-node configurations up to multi-terabyte capacities on 8-GPU platforms.
// Node Scale
Single GPU to Cluster
Compute ranges from single-GPU nodes to 8-GPU HGX platforms to multi-node bare-metal clusters.
// STORAGE

NVMe Storage Architecture

// System Storage
Enterprise NVMe
Dedicated enterprise NVMe system drives handle OS and runtime storage, separate from data storage.
// Data Storage
High-Capacity NVMe
Higher-capacity enterprise NVMe data drives scale with node size to support dataset and checkpoint storage.
// Redundancy
RAID-Managed
Broadcom MegaRAID controllers manage storage redundancy across system and data drives on every node.
// NETWORKING

Interconnect & Fabric

// GPU Interconnect
NVLink / NVSwitch
Connects GPUs within a node for high-bandwidth, low-latency communication on multi-GPU platforms.
// Cluster Fabric
InfiniBand / High-Speed Ethernet
Connects nodes into multi-node clusters over RDMA, so cross-node traffic bypasses the standard network stack.
// DPU Offload
NVIDIA BlueField-3
Offloads networking, storage, and security processing from the host CPU on HGX and cluster platforms.
// DEPLOYMENT

From Lease To Running Workload

Single-node deployments are self-service: select a node, and it's provisioned with the runtime stack already installed. Multi-node cluster deployments follow a structured process instead — consultation, custom cluster design, provisioning, and a defined support SLA. See the enterprise deployment process for details.

// MONITORING

Platform Monitoring

// Infrastructure
Continuous Monitoring
Compute, power, cooling, and network layers are monitored on a continuous basis, so environmental or hardware issues can be caught before they affect running workloads.
// Access & Activity
Ongoing Oversight
Infrastructure and access activity are monitored on an ongoing basis to help catch unusual patterns early.
